with a Bearer header, so its key never appears in a URL. OMDb has no header auth at all — its
key must be a `?apikey=` query parameter.** That is why `omdb.py` must raise `ProviderError`
(which redacts) while `tmdb.py` can keep raising raw `httpx` errors.

convert it to `ProviderError` in this plan. `main.py` line 87 currently does

here would leave an unhandled-exception window across Waves 2-3. Plan 02-04's enrichment layer
catches `(httpx.HTTPError, ProviderError)` together and normalises both.

```python
"""OMDb lookups for the two rating fields that DO have a free API: the real IMDb rating
and the Rotten Tomatoes critic score.

Free key (1,000 requests/day) at https://www.omdbapi.com/apikey.aspx; set it as
OMDB_API_KEY in backend/.env. As with tmdb.py, these functions return None when no key is
configured so the rest of the app keeps working on manually-entered data.

Two things here are security-load-bearing, not stylistic:

1. Lookup is by IMDb ID (`?i=tt#######`), never by title (`?t=`). TMDB hands us an exact
   imdb_id, so a fuzzy title match -- which could silently attach another film's ratings to
   a row -- is designed out rather than mitigated.

2. OMDb has NO header-auth option, so the key must ride in the query string, and httpx
   embeds the full request URL in its exception messages. Every failure path therefore
   raises ProviderError (which redacts in __init__) with `from None` so the original,
   unredacted exception is not chained into the printed traceback.

What is deliberately NOT read from OMDb: `BoxOffice` is domestic-US only, so `gross` comes
from TMDB's worldwide `revenue` instead (RESEARCH section 1). There is no free source for
`rt_aud` or `letterboxd`; those stay manual.
"""
import os
import re

import httpx

from ..redaction import ProviderError

OMDB_BASE = "https://www.omdbapi.com/"
IMDB_ID_RE = re.compile(r"^tt\d{7,10}$")
RT_SOURCE_NAME = "Rotten Tomatoes"
_TIMEOUT_SECONDS = 10


def _api_key() -> str | None:
    return os.environ.get("OMDB_API_KEY")


def _parse_rating_10(value) -> float | None:
    """'9.3' -> 9.3. 'N/A', None, bools, non-scalars, NaN, or anything outside 0-10 -> None."""
    if isinstance(value, bool) or not isinstance(value, (str, int, float)):
        return None
    try:
        rating = float(str(value).strip())
    except (TypeError, ValueError):
        return None
    if rating != rating or not (0.0 <= rating <= 10.0):
        return None
    return round(rating, 1)


def _parse_percent(value) -> float | None:
    """'89%' -> 89.0. Unparseable, NaN, or outside 0-100 -> None."""
    if isinstance(value, bool) or not isinstance(value, (str, int, float)):
        return None
    try:
        percent = float(str(value).strip().rstrip("%").strip())
    except (TypeError, ValueError):
        return None
    if percent != percent or not (0.0 <= percent <= 100.0):
        return None
    return round(percent, 1)


def _extract_rt_crit(ratings) -> float | None:
    """Pull the Rotten Tomatoes critic percentage out of OMDb's Ratings[] array."""
    if not isinstance(ratings, list):
        return None
    for item in ratings:
        if isinstance(item, dict) and item.get("Source") == RT_SOURCE_NAME:
            return _parse_percent(item.get("Value"))
    return None


def parse_omdb_payload(data) -> dict | None:
    """Pure translation of an OMDb response body into our field names.

    Kept separate from the HTTP call so the whole parse matrix is testable with zero
    network and no API key. Every value is type- and range-checked here, because this is
    the boundary where untrusted third-party JSON becomes data we write into
    league_data.json.
    """
    if not isinstance(data, dict) or data.get("Response") != "True":
        return None
    imdb_id = data.get("imdbID")
    return {
        "imdb_id": imdb_id if isinstance(imdb_id, str) and IMDB_ID_RE.match(imdb_id) else None,
        "imdb": _parse_rating_10(data.get("imdbRating")),
        "rt_crit": _extract_rt_crit(data.get("Ratings")),
    }


async def fetch_ratings(imdb_id: str, *, client: httpx.AsyncClient | None = None) -> dict | None:
    """Return {'imdb_id', 'imdb', 'rt_crit'} for an IMDb ID, or None.

    None means either "no API key configured" or "OMDb has no record" -- both are cached by
    the caller as a negative result. Raises ValueError for a malformed IMDb ID and
    ProviderError (message already redacted) for any transport or HTTP failure.

    `client` exists for dependency injection in tests; production callers omit it.
    """
    if not isinstance(imdb_id, str) or not IMDB_ID_RE.match(imdb_id):
        raise ValueError(f"invalid IMDb id: {imdb_id!r}")

    key = _api_key()
    if not key:
        return None

    owns_client = client is None
    client = client or httpx.AsyncClient(timeout=_TIMEOUT_SECONDS)
    try:
        response = await client.get(OMDB_BASE, params={"i": imdb_id, "apikey": key})
        response.raise_for_status()
        data = response.json()
    except httpx.HTTPError as e:
        raise ProviderError(str(e), provider="omdb") from None
    except ValueError as e:
        raise ProviderError(f"omdb returned a non-JSON body: {e}", provider="omdb") from None
    finally:
        if owns_client:
            await client.aclose()

    return parse_omdb_payload(data)
```

Never build the URL by interpolation. `params={"i": imdb_id, "apikey": key}` is required: httpx
percent-encodes dict params, which is what keeps a hostile title or ID from altering the request
target. A literal `f"{OMDB_BASE}?i={imdb_id}&apikey={key}"` would defeat both that and the
redaction regex, and is rejected by this plan's acceptance criteria.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend process -> OMDb (`https://www.omdbapi.com/`) | `OMDB_API_KEY` crosses in the URL query string (no header auth exists). A film title / IMDb ID supplied from `league_data.json` is interpolated into the outbound request. |
| backend process -> TMDB (`https://api.themoviedb.org/3`) | `TMDB_API_KEY` crosses in an `Authorization: Bearer` header, so it is absent from URLs and from httpx error strings. |
| provider JSON -> `parse_omdb_payload` / `_millions` / `_vote_average` | Untrusted third-party JSON becomes values destined for `league_data.json`. This is the validation boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 (origin) | Information Disclosure | `services/omdb.py` failure paths | mitigate | The key is unavoidably in the URL, and `str(httpx.HTTPStatusError)` embeds that URL (verified). Every failure path raises `ProviderError(str(e), provider="omdb") from None`, which redacts in `__init__`; `from None` suppresses the chained original so the unredacted URL cannot reach a printed traceback. `test_http_failure_never_leaks_the_key` asserts both the redaction and `__cause__ is None`. The matching fix at the HTTP response boundary is Plan 02-05 Task 1. |
| T-02-04 | Tampering / SSRF | `omdb.fetch_ratings` request construction | mitigate | Host is a module constant (`OMDB_BASE`), never assembled from data. The only caller-supplied value is `imdb_id`, which must match `^tt\d{7,10}$` *before* a request is built, and which is passed via `params={...}` so httpx percent-encodes it. A string-interpolated URL is forbidden by an acceptance-criteria grep. TMDB's title search is likewise passed via `params`, so a title containing `&`, `?`, or a path traversal cannot alter the request target. |
| T-02-03 | Tampering (data poisoning) | `parse_omdb_payload`, `_millions`, `_vote_average`, `_imdb_id`, `_release_date` | mitigate | Every field crossing from provider JSON into our model is type-checked (with an explicit `isinstance(value, bool)` rejection so `True` cannot become `1.0`), NaN-checked, and range-checked (`imdb` 0-10, `rt_crit` 0-100, money > 0, `imdb_id` against a regex). A malformed or hostile payload yields `None` — which the no-clobber rule in Plan 02-02 then treats as "no value", leaving existing data untouched. |
| T-02-10 | Spoofing (wrong-film substitution) | OMDb lookup key | mitigate | Ratings are fetched by TMDB-supplied `imdb_id`, never by `?t=<title>`, so OMDb cannot return a same-titled different film.
